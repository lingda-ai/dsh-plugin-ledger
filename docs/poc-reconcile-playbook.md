# 对账 PoC 作战手册（2 周 / 3 家）

> 目的：用**接近零的工程成本**验证一个假设——
> **"跨工具、可对账的成本表"有人愿意付钱。**
>
> 不做服务端、不做多租户、不做 UI。只有一份报告和六个问题。

## 0. 为什么先做这个，而不是先写服务端

团队版要投 8–12 人日（上报通道 + 聚合服务）。在写之前必须先知道：**谁付钱、为什么付、付多少。**
这三件事只能靠真人对话回答，不能靠代码回答。一份手工报告就能把对话变成证据。

## 1. 目标客户画像（必须先满足，否则聊了也白聊）

| 条件 | 为什么 |
|---|---|
| 5–50 人研发团队 | 少于 5 人没人管账；多于 50 人走采购流程，周期太长 |
| **同时用 2 种以上 AI 编程工具** | 单一工具的用户厂商控制台就够了，那是我们唯一的结构性差异 |
| 月 AI 支出 ≥ ¥2000 | 低于这个数，"管账"是伪需求 |
| **能拿到上个月的账单**（CSV 或明细页） | 拿不到账单的人，永远不会有对账需求 |

> 反例：个人开发者、纯订阅制（按席位）团队、还没有账单的人。这三类直接跳过。

## 2. 找到 3 家（不要冷启动）

优先级：① 你认识的技术负责人 → ② 社区里问过"AI 账单怎么管"的人 → ③ 朋友圈/群里的团队 leader。

开场话术（不要推销，要数据）：

> 我在做一个 AI 编程成本的对账工具，想免费帮你出一份上个月的对账报告——
> 你把账单 CSV 给我，我给你一份"每天本地估算 vs 账单实际"的差异表，加三条洞察。
> 不需要你装任何东西，数据我当场处理完就删。你只要给我 30 分钟聊一下结论准不准。

**这一步的目标不是成交，是拿到 3 份真实账单。**

## 3. 客户要给什么（最小集）

1. 上个月账单导出（CSV 最好；截图也行，人工转录）；
2. 30 分钟访谈；
3. （可选）一份"你觉得这钱花得值不值"的主观判断。

**不要**代码、不要对话记录、不要账号权限。只要金额。

## 4. 我们交付什么

用 `scripts/reconcile.mjs` 生成一份报告（示例见下）：

```bash
# 1) 客户装了插件的话，直接读本地归档
node scripts/reconcile.mjs --bill 客户账单.csv --from 2026-11-01 --to 2026-11-30 --out 报告.md

# 2) 客户没装：先用他给的用量明细（模型+token）估一份本地口径
#    这一步在 PoC 阶段允许人工做——我们的目标不是自动化，是验证价值
```

报告结构（脚本已生成）：

- 按天的 **本地采集 / 厂商账单 / 差异 / 差异率**
- **未计价条数**（算不出来的部分，绝不当 0 混进总额）
- 模型分布（哪些模型在吃钱）
- "怎么读这份报告"三行说明（把口径写在客户眼前，这本身是信任来源）

**再补三条人工洞察**（这才是客户愿意付钱的部分）：

1. 差异最大的一天，那天发生了什么（模型切换？批量任务？缓存失效？）
2. 有没有"贵但没产出"的模式（同一段上下文反复重发）
3. 如果换一种用法（缓存友好 / 模型降级），这个月大概能省多少

## 5. 30 分钟访谈提纲（按顺序问，别跳）

1. **现在你怎么知道这个月 AI 花了多少？**（听他说"看厂商后台/月底才知道/不知道"）
2. **上一次你因为 AI 成本做过什么决定？**（没有决定 = 没有痛点）
3. **如果发现某个项目/某个人花的钱明显超标，你会怎么处理？**（听"管不管得动"）
4. **这份报告和你现在看到的账单，差在哪？**（评估我们的信息增量）
5. **如果不给你这份报告，你会怎么把这件事做出来？**（替代成本 → 定价锚点）
6. **这份报告如果每月一份，谁批这个预算？大概什么量级？**（不要问"你会付吗"）

> 第 5、6 题是定价探针。**不要主动报价**，让他先说数字或让沉默多停 3 秒。

## 6. 信号判定（2 周后看这个）

| 结论 | 判据 |
|---|---|
| **PASS** | ≥1 家愿意付 ¥2000 试水（哪怕只是买 3 个月报告）；或 ≥2 家明确说"下个月还要"并愿意给账单 |
| **WEAK** | 3 家都说"有意思"，但没人愿意给钱或给数据 |
| **FAIL** | 拿不到 3 份账单；或都说"厂商后台够了" |

- PASS → 立刻投 P3（上报通道 + 聚合服务），因为付费意愿已验证。
- WEAK → 回头做 P0/P1（把单机体验做到值得付费），**不要**写服务端。
- FAIL → 停止 SaaS 方向，转"高质量开源工具 + 内容/咨询"。

## 7. 合规与隐私（第一次沟通就要说清）

- 只处理**汇总金额**；不碰代码、不碰对话、不碰账号。
- 数据在**本地**处理，报告发出后删除原件（或客户自己保管）。
- 客户若已装插件：归档在 `~/.dsh/ledger/archive/`，只有 token 数与金额，没有对话内容；`actor`（git email）默认不写。
- 报告里不出现人名（除非客户明确要求做"按人"视图）。

## 8. 时间盒

| 天 | 动作 |
|---|---|
| D1–D2 | 列出 10 个候选，按"有账单 + 多工具"筛出 3 个，发出开场话术 |
| D3–D7 | 收账单、跑报告、补三条洞察 |
| D8–D12 | 三家各 30 分钟访谈，记录原话（尤其是第 5、6 题） |
| D13–D14 | 汇总信号 → PASS / WEAK / FAIL，写进 `docs/poc-results.md` |

## 9. 你会得到什么（即使全部 FAIL）

1. 3 份真实账单的**口径差异**（价表准不准、缓存计价对不对）——这是产品最缺的校验数据；
2. 一句能写进 README 的话：「我们和 3 家团队对过账，差异率从 X% 降到 Y%」；
3. 一个明确决定：写不写服务端。**这比再写 10 个功能值钱。**

## 附：报告样例（合成数据）

```markdown
| 日期 | 本地采集 | 厂商账单 | 差异 | 差异率 | 条数 | 未计价 |
|---|---:|---:|---:|---:|---:|---:|
| 2026-11-18 | 0.0084 | 0.0087 | -0.0003 | -3.4% | 3 | 1 |
| 2026-11-19 | 0.0051 | 0.0053 | -0.0002 | -3.8% | 1 | 0 |
| **合计** | **0.0135** | **0.0140** | **-0.0005** | **-3.6%** |  | **1** |
```

差异为负的解释固定两条：**价表滞后**、**未计价条目**——这两条恰好也是我们要在 P0 里修的东西。
